# Contract Change Request: m28-01

**Sequence:** 01

## Change requested

Add `INTEL_CLAIM_EXTRACT` to the LLM prompt registry in `specs/contracts/05-llm-prompts.contract.ts`.

## Motivation

M28 requires an LLM extraction step to parse atomic intelligence claims from news source text (event title + description). This prompt drives the `intel-claim-extract` worker. Without a registry entry, the prompt exists only inline in the worker — violating the contract discipline that all LLM prompts must be registered for quality-regression correlation.

## Proposed entry

```typescript
const IntelClaimExtractInputsSchema = z.object({
  title:       z.string(),
  description: z.string(),
  source_name: z.string(),
  source_url:  z.string(),
});

const IntelClaimExtractOutputSchema = z.object({
  claims: z.array(z.object({
    claim_text:  z.string(),
    claim_type:  z.enum(['fact', 'inference', 'forecast']),
    evidence_url: z.string(),
  })).max(5),
});

export const INTEL_CLAIM_EXTRACT = {
  id: 'INTEL_CLAIM_EXTRACT',
  version: '1.0.0',
  model: 'claude-haiku-4-5',
  system: 'You are an intelligence analyst. Extract discrete, verifiable claims from a news source describing a geopolitical event. Each claim must be atomic (one fact per claim), precisely worded, and classifiable as: "fact" (observed/reported), "inference" (derived from facts), or "forecast" (projection of future state). Return only valid JSON.',
  template: `Event title: {{title}}
Event description: {{description}}
Source: {{source_name}} ({{source_url}})

Extract up to 5 atomic claims from this event. For each claim return:
- claim_text: one-sentence statement of the claim
- claim_type: "fact" | "inference" | "forecast"
- evidence_url: the source URL

Return JSON: { "claims": [ { "claim_text": string, "claim_type": string, "evidence_url": string } ] }`,
  expected_inputs: IntelClaimExtractInputsSchema,
  expected_output_format: IntelClaimExtractOutputSchema,
} satisfies PromptRegistryEntry<typeof IntelClaimExtractInputsSchema, typeof IntelClaimExtractOutputSchema>;
```

## Interim state

Until this CCR is approved, `apps/worker/src/workers/intel-claim-extract.ts` uses the identical system prompt and user template via `callLLMJson` from `packages/llm`. The prompt text is consistent — only the registry registration is pending.

## Impact

- Low risk. Additive change only.  
- No other modules depend on this prompt yet.  
- Worker's fallback (deterministic extraction without LLM) is in place for environments without `ANTHROPIC_API_KEY`.
