# CCR: Add `resolved` to AlertStatus

## Discrepancy

The M18 buildplan assignment specifies:
- `status` enum: `'open' | 'triaged' | 'resolved' | 'closed'`
- Kanban page with 4 columns: open / triaged / resolved / closed

The canonical contract (`00-data-model.contract.ts`) defines:
```typescript
export type AlertStatus = 'open' | 'triaged' | 'closed';
```

3 statuses, no `resolved`.

## Proposed Change

Add `'resolved'` to `AlertStatus` in `00-data-model.contract.ts`:

```typescript
export type AlertStatus = 'open' | 'triaged' | 'resolved' | 'closed';
```

## Impact

- `packages/db/models/Alert.ts` — enum array in schema gains one value
- `apps/web/app/app/[orgSlug]/triage/page.tsx` — 4th kanban column unlocked
- No breaking change to existing data; `'resolved'` is additive

## Current Implementation

M18 has been implemented using the 3-status contract (`open | triaged | closed`). The triage kanban renders 3 columns. Merging this CCR enables the 4th column by removing the guard condition in `TriagePage`.
